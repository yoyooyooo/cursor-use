# 产品范围

状态：2026-09-19 已接受的产品方向。本文描述目标与约束，不表示能力已实现；实际进度见[实施路线](../roadmap/implementation-plan.md)。

## 使用者与目的

主要使用者是用户自己的外部 Coding Agent，用户通过对话授权它操作 Cursor Cloud Agent。交付物是独立 CLI 加配套 skill，不要求调用方运行在 Cursor、OpenClaw 或某个固定宿主中。

用户希望完成的完整闭环是：明确任务目标和运行环境，派发，取得可追踪回执，离开后重新找回，查看结果，在同一会话继续工作。还应能查询 Cursor 已提供且经验证可访问的环境与原生 Projects，避免靠猜测选择资源。

术语、状态和数据来源的精确定义由[领域模型](../ssot/domain-model.md)负责。

## 目标范围

| 能力 | 预期结果 |
| --- | --- |
| 身份与能力发现 | 知道当前使用谁的授权、哪些操作可用、哪些受权限或接口缺失限制 |
| 模型与仓库发现 | 使用账号实际返回的目录，不硬编码模型或假设默认分支 |
| 创建任务 | 显式选择仓库、命名环境或经验证的无仓库模式，返回 Agent 和 Run 标识 |
| 跟进与恢复 | 查看状态、等待、读取进度和结果，CLI 重启后仍可继续追踪 |
| 续派与取消 | 在已知 Agent 上发起新 Run，或显式取消指定 Run |
| 费用与产物 | 查询可用的 usage、分支、PR、产物和查看入口 |
| 环境发现 | 清楚说明资源来自权威目录、历史观察还是手工配置，以及列表是否完整 |
| 原生 Projects | 查询真实 Cursor Project 对象；不能用仓库或本地分类替代 |
| skill | 指导外部 Agent 选择目标、提供完整上下文、处理不确定结果和验收 |

机器输出必须稳定、可解析；stdout 用于结果或明确的 JSONL 事件，stderr 用于诊断。0.2 已实现部分的命令、JSON envelope、错误与退出规则见[CLI 契约](../protocols/cli.md)。未被官方接口覆盖的目录能力仍明确受阻，不以模拟数据代替。

## 安全边界

- 凭据不得写入仓库、prompt、日志或调研输出；不自动提取 Cursor.app 或浏览器的登录 Token。
- 创建、续派和可能触发付费执行的诊断须有当前任务授权。查询资源不能暗中启动 Cloud Agent。
- 创建结果不明确时不能假定失败并重新付费派发；恢复规则见[领域模型](../ssot/domain-model.md)。
- 不自动合并 PR，不强制自动开 PR，不修改仓库 origin。显式请求某环境失败时不得静默改投其他环境。
- 不提供永久删除文件或资源的操作；需要资源管理时优先考虑可恢复的归档，并另行明确授权。
- 私有接口不是默认通道。使用前须明确认证、账户一致性、版本约束和用户授权，并保持与公开 API 能力分离。
- 不承诺 Cloud Agent 可直接访问 AGS 或任意内网仓库；连通性和权限须按实际执行环境验证。

## 桌面探索

用户曾授权真实桌面会话与终端互通探索，随后明确停止该方向，收回到官方 Cloud API CLI 与 skill。已有[桌面证据](../evidence/2026-09-19-desktop-poc.md)仅作为历史保留，不再列为待交付或自动恢复的工作。

## 非目标

不重新实现 Agent 推理循环、IDE、云执行平台、复杂任务调度器或全局 Daemon。第一版不做 TUI、通用 MCP 层、远程桌面或全量环境写管理；这些不是派发闭环的前置条件。

## 验收定义

1. 调用方能发现真实身份、可用模型、仓库与资源能力边界。
2. 经明确授权的小任务能完成创建、状态查询、结果读取和同会话续派；有对应真实回执。
3. 本地退出或等待超时不丢失追踪，不误取消云任务；不因响应丢失重复创建任务。
4. 任务结束与业务验收分开说明，PR、测试和产物按任务要求核对。
5. 环境与原生 Projects 的读取经独立验证；不完整或不可用必须如实呈现。任务派发成功不能代表资源管理目标已完成。

实现顺序与尚未验证的前置条件见[实施路线](../roadmap/implementation-plan.md)，验证方法见[验证规则](../standards/verification-policy.md)。
