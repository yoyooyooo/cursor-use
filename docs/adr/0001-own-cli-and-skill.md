# 独立实现 CLI 与 Skill

状态：已接受。2026-09-19 用户认可上一轮自建策略，并指定项目名 `cursor-use`、目录和文档优先初始化。本决策不代表原生环境或 Projects 的访问能力已经验证。

## 背景

用户需要宿主无关的 CLI + skill，控制 Cursor Cloud Agent 并发现相关资源。已有候选要么绑定 GitHub PR 工作流、OpenClaw 或旧 v0 API，要么为 MCP 和高级环境管理引入过大范围；调研未发现可直接满足完整需求且具有长期维护证据的底座。

证据保留在[选型核验快照](../research/2026-09-19-cli-landscape.md)。其中建议属于历史研究；本 ADR 拥有当前已接受的技术选择。

## 决策

- 独立实现小范围的 TypeScript CLI + 配套 skill，不整体 fork 某个候选，也不自建 Agent 执行平台。
- 首选官方 Cloud Agents v1 REST，集中网络和契约处理。官方 SDK 可在证据证明能减少具体复杂度时采用，不再依赖第三方 Cursor SDK。
- CLI 负责执行、校验、回执和恢复；skill 负责解释何时调用、如何提供任务上下文、如何验收，不重复实现网络逻辑。
- 命名环境和原生 Projects 的读取先验证能力，再决定实现。非公开接口独立隔离，不扩大为通用私有 API 代理。
- 不继承强制自动 PR、cwd/origin 绑定、永久删除或复杂后台调度。
- 借鉴候选的设计经验；复制实现前确认许可和保留来源。没有许可证的代码不作为复制基础。

## 代价与重开条件

项目自行承担分页、错误、重试边界、契约漂移和回归测试的维护。自建 CLI 不能解决提供方未开放的接口，环境/Projects 仍可能需要单独授权或保留明确缺口。

如果官方发布完整且稳定的管理 CLI，或官方 SDK 为本需求提供明显更小的维护面，应重新评估适配实现；命令和 skill 的用户语义不应被传输方式绑死。修改本决策时保留历史并通过后续 ADR 说明取代关系。
