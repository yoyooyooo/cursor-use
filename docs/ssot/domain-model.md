# 领域模型

范围：cursor-use 跨命令共享的对象、状态和不变量。基于 2026-09-19 的官方文档及本次选型结论；外部 API 变化时须重新核验，不能把本页当作服务端响应 schema。

## 对象

| 对象 | 含义 | 不应混同 |
| --- | --- | --- |
| Agent | 持有会话上下文和工作空间配置的持续对象，通常具有 `bc-...` 标识 | 一次 prompt 的执行 |
| Run | 向 Agent 提交一次指令的执行，通常具有 `run-...` 标识 | Agent 的长期生命周期 |
| Environment | 执行目标或保存的环境配置；官方目标包括 cloud、pool、machine | 仓库、环境变量或 Project |
| Repository | 可供任务访问的源码仓库及 starting ref | 用户本机当前工作树 |
| Project | Cursor 原生的长期工作对象，包含协调 Agent、共享上下文等 | 本地分组、repo 或名为 project 的环境分类 |
| Task Receipt | 本地保存的派发回执和恢复线索 | 云端状态的最终事实来源 |

官方对象说明：[v1 API](https://cursor.com/docs/cloud-agent/api/endpoints)、[Projects](https://cursor.com/docs/agent/projects)。

## 执行状态

以指定 Run 的响应判断执行状态，而不是只看 Agent 是否 ACTIVE 或 IDLE。原始服务端状态应保留；未知状态不得自行归为成功。

- `CREATING`、`RUNNING` 表示当前 Run 尚未结束。
- `FINISHED` 表示该轮执行结束，不自动证明用户验收通过。
- 错误、取消或过期属于不同结果，不能统一输出为完成成功。
- Agent 的 `IDLE` 只表示可接受续派，也可能出现在可恢复错误之后。
- 同一 Agent 同时只能有一个活跃 Run；`409 agent_busy` 需要等待或显式取消，不能靠盲目重试解决。
- 本地 wait 超时或 CLI 退出只代表停止本地观察，不代表云端任务取消。

## 数据来源与完整性

资源发现至少区分以下含义；字段的最终编码在接口契约落地时确定：

| 来源 | 可声称的范围 |
| --- | --- |
| authoritative | 已验证的提供方目录，在明确账号、权限、过滤和分页范围内成立 |
| observed | 从历史 Agent/Run 等记录中观察到的资源，不证明覆盖全部环境 |
| configured | 用户登记的目标或别名，不证明远端存在或当前可访问 |

每次目录响应须能说明来源、观察时间和完整性。即使 authoritative，也只有读完所声明范围的分页才能声称 complete。缓存不能伪装为实时读回；查询失败不能伪装为空列表；需要鉴权、权限不足、未提供接口与空结果必须可区分。

## 派发与恢复不变量

1. 创建前记录稳定请求标识和预期 Agent 标识，随后补全服务端 Agent/Run 回执。落盘失败或网络结果未知时保留不确定性。
2. 官方文档允许创建请求携带 `agentId`；重复标识返回冲突而非重复创建。超时后先按相同标识回查，不能生成新标识重发。
3. `envVars` 与客户端 `agentId` 互斥。需要 envVars 的模式不能宣称同等防重复保证，须单独设计恢复后再开放。
4. 未验证服务端幂等支持的 follow-up，不自动重发。记录为结果未知并提供回查路径。
5. 本地回执支持并发安全与重启恢复，不靠静默丢弃旧记录维持存储上限；云端读回仍是执行状态依据。
6. named cloud environment 与显式 repos 按官方契约互斥，不为方便而组合非法参数。
7. 指定 ref 时保留准确值；省略表示使用提供方默认值，不由 CLI 猜测 main，也不把未提交本地文件当作云端可见上下文。

回执中的 Run 归属须区分 confirmed、latest-observed 和 operator-selected。后两者分别是观察与人工确认，不是服务端对原始提交的关联证明；较弱来源和晚到错误不能覆盖已经确认的事实。旧回执缺失字段时不自动补造证明。

SSE 的事件 ID 属于某个 Run，是 opaque 续读位置，不是全局唯一业务事件号。result 与 done 可能共享 ID；事件写到 stdout 也不等于下游已经处理。历史过期后的终态快照不等于完整事件历史。

下载得到的本地文件只在传输及所要求的校验完成后才算成功产物。失败残留文件不覆盖、不永久删除，不因文件存在就声称成功。

这些是实现必须保持的语义，不是无条件运行保证。证据要求见[验证规则](../standards/verification-policy.md)，本次验证见[0.2 云端记录](../evidence/2026-09-19-cloud-v02.md)。
