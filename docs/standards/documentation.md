# 文档治理

适用于本仓库的知识维护。规则来自项目采用的公开文档治理约定；贡献者不需要访问维护者的本机路径或外部工作目录。

## 已采用规则

1. 一个有明确范围的含义只设一个当前负责位置。其他入口链接过去，不复制一份相似权威文档。
2. 已接受目标、技术决策、实际实现、运行证据和未来计划明确区分。新日期不自动推翻既有裁决。
3. 从真实问题建立入口，例如术语、命令、源码或失败测试；不要求每次从根 README 顺序读完整套文档。
4. 新目录和拆分必须有独立含义、生命周期、导航或维护压力，不创建空目录或占位标准。
5. 使用英文 kebab-case 路径，README.md、AGENTS.md 等惯例除外；叙述用中文，机器字段和符号不翻译。
6. 版本敏感结论保留来源、日期和适用范围。外部文档、权限或实现变化时重新核验受影响结论。
7. AGENTS.md 保持简短，只留约束、命令和知识入口，不堆放任务状态、凭据和完整研究报告。

当前知识位置在[文档导航](../README.md)登记。变更现行含义先更新负责位置，再修正受影响入口；保留原始研究快照不意味着维持另一套现行规则。

## 核验

修改后检查本地链接及标题锚点、入口可达性、角色与当前状态是否一致、是否出现模板占位，以及新文档是否有真实维护目的。具体执行范围见[验证规则](verification-policy.md)。
